# 实证研究工作流

八个阶段，从识别策略到复现包。表里的 `AI 自主度` 决定我要不要中途停下来问你，
`HITL 节点` 写明停下来时你要拍板什么。

本目录和仓库其余部分是两条独立的线：根目录那套流水线做**文献综述**（读别人的论文），
这里做**实证研究**（自己跑数据）。两条线不共享目录，也不共享脚本——
根目录的技能和代理里写死的相对路径，在这里一个都不能用。

第一节先交代为什么这样分工，第二节起是流水线本身。
**投稿前必读第八节**——那里列的是只能由研究者亲自做的判断，机器一条都代劳不了。

---

## 一、分工原则

Korinek (2024, JEL) 的综述把生成式 AI 在经济研究中的用途分为六类：创意激发、写作辅助、
背景检索、数据分析、编程实现、数学推导。这条流水线只覆盖其中两类——**数据分析和编程实现**。
它们占实证研究总耗时的大头，也是 Claude Code 当前最擅长的领域。这一选择背后有三条原则。

**第一条：识别假设、样本定义、结论措辞由研究者主导。**

Korinek (2025) 反复强调，多智能体系统擅长承担子任务分工，但研究设计的顶层决定不能外包。
Ludwig 等人 (2025) 进一步指出，用 LLM「分析」数据得到的是预测性相关，因果识别需要研究者
对识别假设承担责任，不能由模型代劳。识别假设选错了，后面所有估计的可信度都归零——
这是研究者无法回避的专业判断。

**第二条：数据拉取、稳健性矩阵、表格图形排版可以大量交给 AI。**

这三类工作目标明确、验证容易，Brynjolfsson 等人发现的生产率提升也集中在这类机械性任务上。
Goldsmith-Pinkham 在 Princeton Markus Academy 系列演示了用 Claude Code 跑 Census 数据管线、
SEC EDGAR 网络爬取、HMDA 18 年面板，自述日常约 90% 的工作通过 Claude Code 完成。
Callaway-Sant'Anna 估计量的作者 Sant'Anna 在个人网站公开了配置，
采用多子代理加质量门禁的工作流。两位活跃的计量经济学家从不同方向印证了这条路径可行。

**第三条：数据清洗与主回归规范是混合区，必须设 HITL 节点。**

清洗脚本 AI 写得很快，但「删哪些异常值、保留哪些样本」是关于研究设计的判断；
主回归的固定效应结构和聚类层级，AI 可以给出常见做法，但最终规范必须研究者亲自审定。

> 上面四条文献还没过引用核验流水线，作者、年份、出处待核。

## 二、流水线

| # | 阶段 | 内容 | AI 自主度 | HITL 节点 |
| --- | --- | --- | --- | --- |
| 1 | 研究问题与识别假设 | 确定因果逻辑、选择识别策略 | 低（辅助） | **必须** |
| 2 | 数据拉取 | API 调用、批量下载、格式解析 | 高 | 否 |
| 3 | 数据清洗 | 缺失处理、异常检测、频率对齐、面板平衡 | 中 | 样本规则需确认 |
| 4 | 描述统计与可视化 | 汇总表、分布图、时序图 | 高 | 否 |
| 5 | 主回归 | 因果识别方法实现、系数提取 | 中 | 规范需确认 |
| 6 | 稳健性检验矩阵 | 替换估计量、控制变量、样本范围 | 高 | 矩阵边界需确认 |
| 7 | 表格图形生成 | LaTeX / RTF 输出、期刊格式 | 高 | 否 |
| 8 | 复现包组织 | 目录结构、README、数据说明 | 高 | 结论措辞需确认 |

### AI 自主度怎么读

| 档位 | 意思 | 我会怎么做 |
| --- | --- | --- |
| 低（辅助） | 决定权在你，我只负责把选项摆全 | 每个岔路口都停下来问 |
| 中 | 我按默认值往前跑，关键规则定稿前停一次 | 每个阶段停一次 |
| 高 | 我一路跑完，出问题再报 | 不打断 |

**五个卡点，一个都不能省。** 阶段 1 是「必须」，其余四个是「确认」——
识别策略没定下来，后面七步全是白跑。

## 三、各阶段

### 1. 研究问题与识别假设 · 低 · 必须

我做的：把问题拆成「处理 — 结果 — 机制」三段，列出候选识别策略，
每条标出它依赖什么假设、假设不成立会往哪个方向偏、需要什么数据才够。

**你拍板的**：用哪个识别策略。

不替你选，是因为这一步错在后面补不回来。策略定了再往下走。
辅助工具：`/method-advisor` 技能（读 `references/` 下的方法卡，给建议但不替你决定）。

### 2. 数据拉取 · 高

我做的：调 API、批量下载、解析格式、落盘原始数据。

这一步全自动，但有个前提——**原始数据落盘之后只读**，清洗一律另存。
拉了就不回头改，否则跑完发现数字不对，无从判断是数据脏还是脚本错。

### 3. 数据清洗 · 中 · 样本规则需确认

我做的：缺失值处理、异常值检测、频率对齐、面板平衡，每条规则都记下影响多少观测。

**你确认的（样本规则）**：

- 缺失值怎么处理——删、插补、还是留哑变量
- 异常值缩尾的阈值定在多少
- 频率对齐用哪个口径（年末值、年均值、还是季度加总）
- 面板是平衡还是非平衡，掉出样本的个体怎么算

**每条规则都要报「剔除多少观测、占样本多少」**，不能只给最终样本量。
最后样本是怎么从原始数据一步步筛出来的，流程图要能画出来。

### 4. 描述统计与可视化 · 高

我做的：汇总表、分布图、时序图，脚本一键生成。

不停下来问，但**图表全部由脚本产出**，不许在 Excel 里手工调。
手工调过的图下次重跑就对不上。

### 5. 主回归 · 中 · 规范需确认

我做的：按阶段 1 定的策略写估计、提系数、算标准误和置信区间。

**你确认的（模型规范）**：

- 固定效应加在哪一层（个体、时间、还是双向）
- 聚类层级，以及为什么是这一层
- 控制变量的取舍
- 标准误类型（聚类稳健、异方差稳健、还是自助法）

**系数表和前面的描述统计必须来自同一个样本。** 样本对不上，系数没法解释。

辅助工具：`/did-estimate` 技能。它把脚本的参数区和
`.claude/rules/regression-spec.md` 的默认值并排打出来、按
`references/did-checklist.md` 列出待检验的假设，**然后停下来等你确认**。

### 6. 稳健性检验矩阵 · 高 · 矩阵边界需确认

我做的：按你划的边界逐格执行，替换估计量、增删控制变量、缩放宽窄样本范围，
把结果铺成矩阵，每格报损、留指纹。

**你确认的（矩阵边界）**：换哪些、试到什么程度算够。边界写在
`config/robustness-matrix.R` 里——四个维度各有哪些可选值、这次跑哪些格子。
**改这个文件就是改边界**，脚本照着它跑，两边不互相抄。

配置里的 `MATRIX_CONFIRMED` 不是 `TRUE`，脚本拒绝执行。

这一格的边界靠你划，我不替你决定「稳健性做到哪种程度可以收手」。

工具：`code/06_robust/06_robust.R` 执行；`estimator-agent` 负责跑完并核对
「配置要的格子都跑到了」；`robustness-reviewer` 做对抗式审阅。
三个角色谁干什么、为什么审阅必须是另一个上下文，见 `CLAUDE.md` 第十二节。

### 7. 表格图形生成 · 高

我做的：LaTeX 输出和图形导出，按目标期刊格式排版，星号、标准误、样本量一次写全。

表里每个数字都从阶段 5、6 的结果文件里读，不允许手敲。

**出表之前先对账**，这是这一阶段真正花时间的地方，也是它比看上去重要的原因：

- 阶段 06 的基准格和阶段 05 的主回归必须是同一个数（同一估计量、同一份数据、
  同一个种子），对不上说明两处不是同一套口径
- 同一规范用两种实现各估一遍（`feols` 的 `|` 吸收 vs `lm` 的哑变量展开），
  点估计应当逐位相同——不同就基本可以锁定代码错误

工具：`code/07_tables/07_tables.R`。

**正文展示哪几列由你定**（脚本参数区的 `DISPLAY_CELLS`）。附录永远是完整矩阵，
不受这个选择影响——见下一条红线。

### 8. 复现包组织 · 高 · 结论措辞需确认

我做的：目录结构、README、数据说明、运行顺序，整理成一个能从头跑到尾的包。

**你确认的（结论措辞）**：正文里怎么描述结果。

措辞强度跟着识别策略走：
DID / IV 的结论写「在某某假设下，估计结果支持……」，不写成「已证明」；
OLS 和相关性分析写「与……正相关」，不写成「导致」。

## 六、规则基座

`CLAUDE.md`、`.claude/rules/`、`.claude/hooks/`、`references/`，
加上仓库根的 `.claude/agents/`、`.claude/skills/`，合起来构成项目的规则基座。

| 位置 | 管什么 | 现有文件 |
| --- | --- | --- |
| `CLAUDE.md` | 定约束大方向 | 路径、种子、版本、命名、披露、HITL、提交、写法约定、AI 边界、子代理分工、矩阵纪律 |
| `.claude/rules/` | 管具体写法 | `regression-spec.md` |
| `.claude/hooks/` | 写 `.R` 时的自动检查与门禁 | `check_r_traps.py`（PreToolUse + PostToolUse）、`check_hitl_stop.py`（Stop） |
| `references/` | 给研究者随时查阅的方法论诊断卡 | `did-checklist.md`、`iv-validity.md`、`rdd-bandwidth.md`、`ai-disclosure-template.md`、`academic-integrity.md` |
| 根 `.claude/agents/` | 阶段 6/7 的执行与审阅代理 | `estimator-agent.md`、`robustness-reviewer.md` |
| 根 `.claude/skills/` | 需要人中途把关的环节 | `method-advisor`、`did-estimate` |

**加载方式的区别要分清楚。**

- `.claude/rules/` **不会被自动加载**，靠 `CLAUDE.md` 第七节指过去才起作用
- `.claude/hooks/` 里的脚本不会自己跑——起作用的是**仓库根**的 `.claude/settings.json`，
  它把事件挂到脚本上
- 根 `.claude/agents/` 和 `.claude/skills/` 同理，**只从项目根发现**

所以配置和代理/技能定义都在仓库根，脚本和规则文件在本目录。

### hook 怎么接的

`.claude/settings.json` 挂了三个事件：

| 事件 | 干什么 |
| --- | --- |
| `PreToolUse`（Write\|Edit\|MultiEdit） | 涉及随机数的 `.R` 里没 `set.seed` → `exit 2` **拦住写入** |
| `PostToolUse`（Write\|Edit\|MultiEdit） | 文件已落盘，读磁盘上的成品，把四类写法提示回灌给模型 |
| `Stop` | 仓库处在两个过渡点上时提醒研究者审阅（其余时候静默） |

三点坑，都是实测/查证过的：

**① 教程那份 hook 配置用的是 `$CLAUDE_FILE_PATH`，那个变量不存在。**
当前版本里路径只能从 stdin 的 JSON 里取（`tool_input.file_path`）。
照教程抄会得到一个永远拿不到文件名的 hook——守看着在守，其实没守。

**② `Edit` 的 `tool_input` 里只有改动片段，没有整份文件。**
所以「看整块」的检查（`feols(` 有没有配 `cluster`）在 `PreToolUse` 做不了——
那时文件还没写。放 `PostToolUse`，从磁盘读，拿到的是真正的成品。

**③ Windows 上 hook 走 bash 执行，反斜杠路径会被吃掉。**
所以 `command` 里用正斜杠 + `$CLAUDE_PROJECT_DIR`，并且显式写出解释器
（`.venv/Scripts/python.exe`）——裸的 `.py` 路径不会被当成可执行文件。

hook 的具体判准见 [CLAUDE.md](CLAUDE.md) 第九节。**只有「缺种子」一条会拦截**，
其余只提示——判准是「检查客观、没有合法例外、漏掉的后果静默」三条同时成立。

`Stop` 事件的实际触发时机和直觉不同：它在**主 agent 每答完一轮**时触发，
不是会话结束时。所以 `check_hitl_stop.py` 只在仓库状态真的处在过渡点上才吭声
（主表已生成而矩阵没跑、或矩阵已生成而表没出），其余时候一句话都不说——
**一条每次都出现的提醒，等于没有提醒。**

## 七、红线

- **原始数据只读。** 清洗结果另存，绝不覆盖 `data/raw/`。
- **表和图全部脚本生成。** 手调过的数字下次重跑就对不上，对不上就等于没有。
- **四处由人定稿才往下走**：样本规则、模型规范、矩阵边界、结论措辞。
  这四处我给出方案和代价，决定权在你。
- **不编造数字。** 跑不出来就报「跑不出来」，让它缺着，也不拿近似值顶上。
- **AI 只跑代码、不读数字。** 系数解读、假设判断、稳健性结论由研究者撰写；
  每个结果都要能追到数据指纹。见 `CLAUDE.md` 第十节。
- **清洗和回归都要报损失。** 每一步剔掉多少观测、占多少比例，逐条记。
- **稳健性矩阵完整进附录，符号翻转的格子不许删。** 跑不成的格子也要在附录里
  有行并写明原因。正文可以只展示 3-4 列，但要说明为什么这么挑。
  删掉一格省不了多少版面，却把「检验过」变成了「没检验过」，而读者看不出来。
  见 `CLAUDE.md` 第十三节。
- **结论措辞跟着识别策略走。** 假设驱动的方法写成「在某某假设下」，
  不写成「已证明」。
- **每次运行留日志。** 时间戳、输入文件名、输出文件名、观测数，缺一样就没法复现。

## 八、学术诚信：这几件事只能你自己做

第七节讲的是「脚本不许做什么」，这一节讲「你必须做什么」。
完整版在 [references/academic-integrity.md](references/academic-integrity.md)，这里是提要。

### 五个判断，AI 一个都不能代劳

| 节点 | 你拍板什么 | 落在哪 |
| --- | --- | --- |
| 1 识别假设与方法选择 | 用哪个识别策略、平行趋势能不能信 | `code/01_identify/` 决策记录 |
| 2 样本构造规则 | 年份范围、异常值阈值、哪些单元算控制组 | `03_clean.R` 参数区 |
| 3 主回归规范 | 固定效应结构、聚类层级、控制变量集 | `05_main.R` 的 `CONFIRMED` 闸门 |
| 4 稳健性矩阵边界 | 换哪些维度、做到什么程度算够 | `config/robustness-matrix.R` |
| 5 最终表格与结论措辞 | 每个数字亲自核；「显著降低」还是「无显著影响」 | 正文定稿 |

**共同特征：输出质量无法用自动规则检验。** 这正是 Hooks 和 Skills 只在这里
「停下来等你」、而不替你决定的原因——机器能判断「有没有 `set.seed`」，
判断不了「这个识别策略对不对」。

还有一条单独说：**AI 会系统性偏向 DID。** 苏黎世大学的 APEP 全自动管线
（截至 2026 年 3 月约 592 篇）产出的论文里，73.8% 至少三次提及 DID，远高于
NBER 工作论文的比例。本仓矩阵的估计量维度 TWFE / CS / SA **三档全在 DID 家族里**——
跑得再满，也回答不了「这个政策问题该不该用 DID」。那是你的问题。

      跌到 8500，是审稿人最容易发现的一类不一致
