## 依赖：只用 base R

`unzip()`、`read.csv()`、`merge()`、`aggregate()`、`quantile()` 全是 base R /
`utils`，**不需要装任何包**。清洗是整条流水线的入口，入口少一个依赖就少一个
别人复现不出来的理由。

唯一的例外是外部政策文件：base R 读不了 `.dta`，要么装 `haven`，要么在外部整理
阶段就存成 `.rds`。脚本会在遇到 `.dta` 时明确报出来，不假装能读。

## 这份文件是模板，不能直接跑

`03_clean.R` 顶部的「参数区」有七项待确认。**留 `NA` 时脚本会主动中止并列出缺哪几项**，
不会按某个默认值默默跑完。填好再跑。

| 参数 | 待确认什么 | 影响 |
| --- | --- | --- |
| `KEEP_OWN` | 保留哪些所有制（1=联邦 2=州 3=地方 5=私营） | 决定样本口径。只做私营就填 `"5"` |
| `KEEP_IND` | 行业范围（全部行业合计，还是限定行业） | 填合计行才等于「州的总就业」 |
| `KEEP_AGG` | 地区层级（全国 / 州 / 县 / 大都市区） | 决定下面要不要真正做聚合 |
| `AGG_MODE` | 同州同年多行时 `"sum"` 还是 `"mean"` | 县→州必须 `"sum"`；直接选州级则空转 |
| `WINSOR_P` | 缩尾百分位，留 `NA` 则不缩尾 | 只改数值不删观测 |
| `OUTLIER_SD` | 超几倍标准差标旗 | **只标旗，不删除** |
| `PANEL_MIN_YEARS` | 留 `NA` = 非平衡；填 n = 剔除不足 n 年的州 | 决定面板是平衡还是非平衡 |
| `MIN_OBS` | 期望观测数下界 | 末尾守卫用，第一次跑完拿实际值回填 |
| `TREAT_VAR` | 外部文件里标记「该州该年受政策约束」的 0/1 变量名 | 决定 `gvar`（阶段 05 的必需输入）。**外部文件不在时不用填** |
| `UNMATCHED_NEVER` | `"0"`＝缺旗标就报错；`"1"`＝视为从未受处理 | 填 `"1"` 等于宣布一个识别假设，见下 |

**代码列（`own_code` / `industry_code` / `agglvl_code`）的取值不要凭记忆填。**
第一次跑时脚本会在首年把这三列的**实际取值**打印出来，照那个填。

## gvar：本阶段给阶段 05 留的接口

阶段 05 的 `did::att_gt` 要一个 **`gvar`**——每个州「首次受处理年份」，
从未受处理的编码 0。本脚本第 7b 节负责构造它。

**为什么在清洗阶段构造，而不是让主回归脚本现算。** `gvar` 是处理定义，和样本定义是
同一类东西（CLAUDE.md 第七节第 1、2 条）。定死一次、下游全读同一个变量；若放到
05/06/07/08 各自现算，稳健性按队列切样本、表格按队列分组时，四处就可能用四种口径，
而且**没人看得出来**——正是第九节要防的那类错。

构造要外部政策文件和两个参数：

- `TREAT_VAR`：外部文件里标记「该州该年受政策约束」的 0/1 变量名
- `UNMATCHED_NEVER`：外部文件没覆盖到的州怎么算

**`UNMATCHED_NEVER` 是本节唯一需要想清楚的地方。** 面板里有些州没在外部文件出现
（典型情况：从未调整最低工资的州就是不在那张表里）。它们的旗标是缺失。脚本不猜：

- 填 `"0"` → 报错停下，让你去补外部文件
- 填 `"1"` → 视为「从未受处理」，`gvar` 记 0

**填 `"1"` 等于宣布一个识别假设**：「没出现在外部文件里的州 = 从未调整最低工资」。
只有外部文件本身就是一张「受处理州清单」时这个假设才成立。脚本会在日志里
把没覆盖到的行数打出来，供你判断。

第 7b 节有七条守卫，拦的是「构建出一个看着正常、但处理时点算错了的 `gvar`」：
旗标变量在不在、是不是数值型、是不是干净的 0/1、`gvar` 在同州各年是否一致、
取值是否合法、政策是否中途回退、是否还有可比组。另外会打印**处理队列的规模分布**，
并单独告警**只有单个州的队列**（这种 ATT 建立在单个州上，不能直接写进正文）。

**外部文件缺失时整块跳过**：脚本照常跑完，`panel.rds` 里没有 `gvar`，
完成横幅会明说。外部数据是可选依赖，不能因为它缺就让清洗失败。
但 `gvar` 缺了阶段 05 会拒绝运行——那是**有名字的、指向本脚本的**失败，不是静默的。

## 报损：每一步都记

脚本里有个 `report_loss()` 函数，每次筛选都打印
「`n0` -> `n1`，剔除多少（百分之几）」。这是 [README.md](../../README.md) 第六节的红线：
清洗和回归都要报损失，不能只给最终样本量。

`keep_matching()` 把「按代码列筛选」收在一处。它多做一件事：
**筛完剩 0 行时，把参数填的值和该年实际的取值一起打出来**——
填错代码是最容易发生、又最难从结果里看出来的错，这里让它当场暴露。

## 与常见教程写法的差异

| 教程写法 | 这里的写法 | 为什么 |
| --- | --- | --- |
| `use "data/raw/qcew_2000_2019.dta"` | 逐年 `unzip()` + `read.csv()` | 阶段 02 只留年度 zip，不产出合并面板 |
| 键含 `qtr` | 没有 `qtr` | 拉的是 `annual_singlefile`，不是季度文件 |
| Stata `stringcols()` 保前导零 | 全部列先按字符读，再转数值列 | 见已知坑①——R 这边反而省事 |
| 硬编码列名 | 读表头自查，缺列打全表头再中止 | 见已知坑② |
| 外部文件当 master 合并 | 面板当 master（`all.x = TRUE`） | 见已知坑⑥ |
| `_pctile` 缩尾 | `quantile(type = 7)` | **口径不同，未对齐**，见已知坑⑦ |

## 已知坑

**① 前导零——R 这边反而比 Stata 省事。** QCEW 的县码是 `01001` 这种形式。
Stata 的 `import delimited` 会自动推断类型，得专门指定 `stringcols()` 才能保住前导零。
R 这边**先把所有列都按字符读进来**（`colClasses = "character"`），前导零天生就保住了，
再显式把 `emp` / `pay` 转成数值。读入之后脚本还会复核一遍
「`area_fips` 里有没有以 0 开头的值」，等于把这件事测了两次。

**② 列名没核对过。** 本仓从没真下载过 QCEW 数据（`--check` 之外没跑过），
所以 `annual_avg_emplvl`、`avg_annual_pay` 这些列名**是按 QCEW 公布的表结构写的，
没在真实文件上验证过**。脚本因此不硬编码列序：读表头 → 逐列核对 → 缺列就把
该年的实际表头整个打出来再中止。

早期年份布局可能与近年版不同（见 [02_fetch/README.md](../02_fetch/README.md) 已知坑③）。
真跑时若报缺列，照打印出来的表头改参数区的 `VAR_EMP` / `VAR_PAY` / `KEYS`。

**③ 首次运行会很慢，而且很吃内存。** 单年 CSV 解压后约 489 MB、359 万行，
20 年合计近 10 GB。脚本是**逐年读入再 `rbind`**，不是一次性读进来——
但 `acc` 会一直在内存里长大，20 年累积下来的面板本身也不小。
慢是正常的，内存不够就要考虑先压到州级再合并。

**④ `51` 州是硬编码。** 末尾的满面板提示按 50 州 + 华盛顿特区算。
QCEW 州级口径实际是否正好 51 个，等真跑一次看实际州数再定。

**⑤ 外部文件读不了 `.dta`。** base R 没有读 Stata 格式的能力。脚本遇到
`state_min_wage.dta` 会明确报出来并给出两条路（装 `haven`，或另存成 `.rds`），
**不会静默跳过**。

**⑥ 合并方向：R 这边不再是个坑，但值得记住它在 Stata 里是。** Stata 的 `merge`
把「哪一边是 master」编成 `_merge` 的 1/2/3，反着读就会静默删光对照组——
网上大量示例写外部文件当 master 再 `keep if _merge==3`，如果那份外部文件
只是一张「受处理州清单」，这一行就把整个对照组删了，而且全程不报错。

R 的 `merge(..., all.x = TRUE)` 是左连接，语义上天然就是「面板当 master」，
不存在「2 到底是哪一边」这种必须记住的问题。脚本另外做了两件事补上 Stata 自动
帮你做的那部分：**先数出「只在外部文件里」有多少行并报损**，
**再检查两边有没有同名变量**（Stata 会因此报错，R 会静默加 `.x`/`.y` 后缀）。

**⑦ 缩尾的分位数口径和 Stata 不一样，没有对齐。** R 的 `quantile(type = 7)`
和 Stata 的 `_pctile` 在样本量小或有并列值时给出的分位点会差一点点。
差别只影响边缘观测，但既然口径不同就该说明白——换成 Stata 重跑时
缩尾后的系数可能不是逐位相同的。要完全对齐得手动实现 Stata 的算法。

**⑧ 表头可能带 UTF-8 BOM。** 有些年份的 CSV 第一列名字会是 `"﻿area_fips"`（前面多一个
看不见的 BOM 字符），此时按名字取列会**全部取不到**，而报错信息完全看不出是 BOM 干的。
脚本在读表头和读入之后各抹一次 BOM，属于防御性处理——QCEW 文件到底有没有 BOM，
没下载过数据，**没能核实**。

**⑨ 全缺失的州-年会被 `sum(na.rm = TRUE)` 变成 0。** R 的 `sum(c(NA, NA), na.rm = TRUE)`
返回 `0` 而不是 `NA`。如果某个州-年的 `emp` 全是缺失，collapse 之后就是 `0`，
取对数得 `-Inf`——那不是 `NA`，`is.na()` 抓不到，却会让后面所有回归系数变成 `NaN`。
所以第 8 节的第三条守卫查的是 `is.finite()` 而不只是 `is.na()`，并会把出问题的州-年打出来。

**⑩ `gvar` 尚未在真实数据上验证过。** 第 7b 节的构造逻辑
（取旗标=1 的最早年）依赖外部文件的形态，而那份文件不存在。守卫能拦住
「旗标不是 0/1」「同州 `gvar` 不一致」这类结构错误，但**拦不住「旗标列选错了变量」**
——选错一列，`gvar` 结构完全合法，处理时点却是错的。所以 `TREAT_VAR` 必须
对着外部文件的实际列名填，不要凭理解猜。
