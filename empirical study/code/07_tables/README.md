## 这个脚本的第一件事不是出表，是对账

出表之前先做两件核对，因为**表格出错最常见的方式不是数字算错，是数字对不上号**：

**核对一：格子数与配置一致。** 读 `config/robustness-matrix.R`，
比「配置要求几格」和「`cells.csv` 里有几格」。少一格、多一格都报出来。

**核对二：与阶段 05 对账。** 配置里的 `BASELINE_CELL` 那一格，和
`output/tables/tab_main.csv` 里 `CS-DID` 的 `att` 应当是**同一个数**
（同一估计量、同一份数据、同一个种子）。对不上说明两处不是同一套口径——
**这是最容易发生、也最难从版式上看出的错**。

顺带核数据指纹：两份结果文件如果 `data_md5` 不同，说明它们读的不是同一份面板，
那上面这个「差多少」就没有意义，脚本会明确指出。

## 与教程写法的差异

| 教程写法 | 这里的写法 | 为什么 |
| --- | --- | --- |
| `esttab ... using tab_main.tex` | 手写字符串 + `writeLines` | `aggte()` 返回的不是模型对象，喂给 `esttab` 的对应物（`modelsummary` / `etable`）都要额外搬运。手写零依赖，格式也看得见 |
| `csdid_plot` | `did::ggdid()`，在 `05_main.R` 里画 | 每个脚本只画自己那一段的图，事件研究图不在这里重画 |
| `coefplot` | `ggplot2` 森林图 | 一个格子一个点、一条 95% 区间，横轴 ATT。基准格单独标色 |
| 「Stata 的 `reghdfe` 和 R 的 `feols` 对不上就说明代码错了」 | **`feols` vs `lm`** | 本仓只有 R，两种工具链无从谈起。同一份数据、同一规范，`feols` 用 `\|` 吸收固定效应、`lm` 把固定效应展开成哑变量——**都是 OLS，点估计应当逐位相同** |

**只比点估计，不比标准误。** `feols` 那栏是聚类标准误、`lm` 是经典同方差标准误，
两者按构造就该不同，比它等于自找误报。要点估计一致就够了——它能抓住
「固定效应没吸收对」「样本被悄悄改过」这类代码错误。

> 两边对不上时先查一件事：`fixest` 默认会丢掉单例组（`fixef.rm`），`lm` 不会。
> 样本量不同，系数自然不同。mpdta 是平衡面板、没有单例组，所以正常情况下应当一致。

## 参数区：正文展示哪几列是你的事

`DISPLAY_CELLS` 决定正文表有哪几列。脚本给了一组默认挑法
（基准格 + 每个维度各变一次），但**挑哪几列等于决定读者看到什么**，
这件事不该由默认值代劳。出正文前自己看一眼，不满意就改这个向量重跑。

**附录表不受它影响。** 附录永远是完整矩阵。

## 已知坑

**① 星号是从正态近似反推的 p 值判的。** `aggte()` 的自助法标准误、
`feols` 的聚类标准误都是渐近正态的，`2 * pnorm(-|t|)` 这个近似站得住；
**但它是近似，不是估计量给出的原始 p 值**。要精确 p 值得从各估计量的
结果对象里直接取——现在没这么做，因为要按估计量分四种取法，而矩阵里
混着四种估计量。**这是明写的取舍，不是疏漏。**

**② 没跑成的格子会以「—」进附录表，并在表下逐条列出原因。**
不列的话，一排「—」看上去像「跑了但没结果」，和「根本没跑」分不开。

**③ 不重画事件研究图。** 它在 `output/figures/fig_event_study.pdf`，
由 `05_main.R` 产出。两个脚本画同一张图，迟早画成两个样子。

**④ 森林图只画 `status == "ok"` 的格子。** 失败的格子画不出来（没有 `att`），
但它们**在附录表里有行**。图不是完整性的凭据，附录表才是。

## 红线

**符号翻转或显著性消失的格子，不许从附录里删掉。**
稳健性检验最大的诱惑是只报告支持主结论的列。完整矩阵本身就是诚信证明
（[README.md](../../README.md) 第七节）。正文里少放几列是可以的——
但要说明为什么这么挑，而且附录里那一格要留着。
