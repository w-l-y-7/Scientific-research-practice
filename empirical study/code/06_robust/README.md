# 阶段 06 · 稳健性检验矩阵

对应 [CLAUDE.md](../../CLAUDE.md) 第七节第 4 条 HITL 节点、[README.md](../../README.md) 第三节阶段 6。
按 `config/robustness-matrix.R` 划定的边界逐格执行，**一个脚本跑完整个矩阵**。

```powershell
# 在 R / RStudio 里（不是 PowerShell）。先 cd 到 empirical study/，再 source
setwd("d:/git仓库/Scientific reacher practice/empirical study")
source("code/06_robust/06_robust.R")
```

## 矩阵边界在哪

**不在这个脚本里，在 [config/robustness-matrix.R](../../config/robustness-matrix.R)。**
四个维度（估计量、控制变量集、样本范围、结果变量）各自的可选值、要跑哪些格子、
基准格是哪个，全在那一个文件里。

这样分是因为矩阵边界是 HITL 节点：研究者改配置，脚本照着跑，两边不互相抄。
配置里 `MATRIX_CONFIRMED` 不是 `TRUE` 时脚本**拒绝执行**。

## 闸门为什么放在配置里，不放在代理的提示词里

`/did-estimate` 那条路能在中间停下来等人，是因为它跑在**当前对话**里。
子代理是独立上下文，**跑完才交结果回来，没法中途暂停**。所以：

- 需要人把关的那一步（打印边界、停下确认）在主对话里做
- 代理这侧只留一道硬闸门：不是 `TRUE` 就拒绝执行

两道都要有，因为它们拦的是不同的失败模式——主对话那道拦「没想清楚就确认」，
配置这道拦「改了配置顺手一跑」。

## 与教程写法的差异

| 教程写法 | 这里的写法 | 为什么 |
| --- | --- | --- |
| 每格生成一个临时 `.do`，逐个 `stata-mp -b do` | 一个 `.R` 内循环 | 每格一个文件是 Stata 分批执行模型的产物，不是设计选择。R 用循环 + `tryCatch` 拿到同样的隔离（一格炸了不影响其他格），不用管临时文件的命名冲突和清理 |
| `config/robustness-matrix.yaml` | `config/robustness-matrix.R` | 样本规则本身是 R 表达式。放进 YAML 就得 `eval(parse(text = ...))`——那是把配置当代码执行，拼错的规则会静默变成别的规则。另外省掉 `yaml` 包 |
| 每格一个 `cell_XX.json` + `summary.json` | 一个累积的 `cells.csv` | 网格结果是纯表格，`write.csv` 自带转义（手写 JSON 要自己处理引号换行）。**每跑完一格就重写一次**，中途崩了已完成的格子还在文件里 |
| 估计量三维：TWFE / CS / SDID | TWFE / CS / **Sun-Abraham** | `synthdid` 没装，且它的接口在渐进采纳下的写法**我没能核实**。不实现就不写。换成 `fixest::sunab`——它和 CS 是两种不同的负权重修正路线，且随 `fixest` 一起来，零额外依赖。SDID 那一格留着位置，见下 |
| 样本三维：全样本 / 排大州 / 排危机年 | 全样本 / 排大县 / 排末期 | mpdta 是县级、只到 2007。真正的危机年（2008-09）不在样本里，所以最后一刀切的是「危机前夜」那一年——**这是与教程不同的一刀** |
| 样本三维含「平衡面板」 | 去掉了 | mpdta 本来就是平衡的（500 县 × 5 年），这一档是空转。留着会跑出一个和 `full` 完全相同的格子，让人以为做了检验 |
| `set seed 20260417`（每个 do 文件首行） | `set.seed(20260417 + 格序号)` | 每格独立种子：重跑单独一格能复现，格与格之间不共享随机数流。种子写进结果文件 |
| `datasignature` | `saveRDS` + `tools::md5sum` | 母本面板一个指纹；各格都是它切出来的子集，指纹 + 每格样本量能还原出这格读的是哪份数据 |
| 子代理生成 do 文件并解析 `.log` | 脚本自己写结果文件，代理只负责跑和对账 | 让数字只经过一条路径。代理去解析日志文本，等于多一层会认错数的环节 |

## 产物

| 路径 | 内容 |
| --- | --- |
| `output/robustness/cells.csv` | 逐格结果。**每跑完一格重写一次**，中途崩了不丢已完成的格子 |
| `logs/06_robust_YYYYMMDD_HHMMSS.log` | 完整运行记录，含每格的报损 |

`cells.csv` 的列：`cell_id`、四元组（`est`/`ctrl`/`sample`/`outcome`）、
`status`、`att`、`se`、`ci_lo`、`ci_hi`、`n_obs`、`n_units`、`n_treated_units`、
`cluster`、`seed`、`data_md5`、`note`。

`status` 三档：`ok` / `error` / `not_implemented`。**失败也留一行**——
悄悄少一格，汇总表就少一列，而且事后无从分辨「跑了但结果不好看」和「根本没跑」。

## 样本维度是唯一允许重切样本的地方

[CLAUDE.md](../../CLAUDE.md) 第九节要求「样本筛选集中在 `03_clean.R`」，
主回归脚本一律不筛选。**阶段 06 是这条规则的唯一例外**，因为它的样本维度
就是要一遍遍重切样本。

例外不是豁免，附带三条约束：

1. 每一刀都必须写在配置里（不是散在代码里），所以「切过哪几刀」是可清点的
2. 每格都要报损：日志里逐格打印 `n0 -> n1，剔多少（百分之几）`
3. 每格的 `n_obs` 进结果文件，由 `robustness-reviewer` 核对
   **「样本维度的 N 和 `full` 一样」= 那一刀没切到东西**，比跑失败更危险

## 已知坑

**① SDID 那一格没有实现。** 教程的估计量维度有第三档 SDID，这里的 `sa`
是替代品。要补 SDID 的话，先跑 `?synthdid_estimate` 把接口确认下来，
再改 `06_robust.R` 里 `est == "sdid"` 那个分支——现在它会记一行
`status = "not_implemented"`，**留痕，不静默跳过**。

**② `sa` 格的汇总接口没核实过。** Sun-Abraham 出来的是各期系数，要汇总成
一个数才进得了矩阵，脚本用的是 `summary(fit, agg = "att")`。这个接口
**我没有把握**（本机没装 R，没法核）。跑不通会记成 `error` 并写明原因，
不会拿别的数顶上。第一次真跑若报错，把报错信息拿过来按实际接口改。

**③ `level` / `ihs` 两档是反推出来的。** mpdta 只给了一个结果变量 `lemp`，
水平值是 `exp(lemp)`、IHS 是 `asinh(exp(lemp))`。如果 `lemp` 当初是按
四舍五入后的数取的对数，`exp(lemp)` 只能近似还原。这两档检验的是**函数形式**，
不是数值精度，所以可以接受；但别把 `exp(lemp)` 当原始就业数用。

**④ 排末期那一刀可能让某个队列失效。** mpdta 里 2007 年首次受处理的县，
去掉 2007 之后就没有处理后时期了。`att_gt` 会因为队列缺处理后期报错或丢弃它，
那一格会记成 `error`。**这是有意义的结果，不是脚本 bug**——
它说明「排除末期」这一刀在这份数据上切掉的不只是时间，还切掉了一个队列。

**⑤ 报损的样本量口径。** `drop_large` 的阈值 `lpop_p90` 是按**整份面板**定的，
不随每格的子样本漂。理由：阈值要是跟着子样本走，「切样本」和「改阈值」两个
维度就混在一起了，看不出是哪一刀起的作用。代价是这一刀的口径和「对每个
子样本分别缩尾」的做法不同——**这两种做法都有人用，这里是明写的一种**。
