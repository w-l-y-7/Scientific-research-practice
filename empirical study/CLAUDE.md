## 三、软件版本锁定

- 每个 `.R` 文件首部必须写 `stopifnot(getRversion() >= "4.4.0")`
- 用到外部包时，脚本开头要**显式检查包在不在**，缺了就把 `install.packages(...)` 的
  命令原样打出来再中止，不要让脚本半路炸在一句看不懂的报错上
  （`05_main.R` 第 0 节和 `03_clean.R` 的依赖说明是范例）
- Python 脚本跑在仓库根的 `.venv`（Python 3.14.3）。能只用标准库就只用标准库；
  确需第三方包时，先在根 `requirements.txt` 锁定版本再装，不要在会话里临时 `pip install`
- 依赖的 R 包版本记录在 `README.md` 第五节「计算环境」段
- **不升级已装依赖，除非全员同步。** CRAN 没有「装旧版」的默认开关，
  所以本项目的做法是：把 `packageVersion()` 的实际输出抄进 README 计算环境节，
  作为版本锁定的落点。升级前先记下当前版本号

## 四、变量命名约定

- 一律小写下划线
- 时间变量统一 `year`（整数）或 `yq`（季度序号）
- 个体 ID 统一 `state_id`（州）或 `cty_id`（县）
- 处理变量（标记是否接受政策的 0/1 变量）`treat_*`，结果变量 `y_*` 或语义变量（`log_emp`、`wage_level`）

## 七、人在回路（HITL）节点

以下节点必须由研究者确认，Claude Code 执行到此处应暂停并请求人工审阅：

1. 识别假设与研究设计（因果逻辑和方法选择由研究者在项目启动时确定，AI 不代为决定）
2. 样本筛选规则确定（`03_clean.R` 里的筛选规则）
3. 主回归规范确认（固定效应结构、聚类层级）→ 落到脚本里的 `CONFIRMED` 闸门
4. 稳健性矩阵边界确定（跑哪些列）
5. 最终表格的结论措辞

第 1、3、4 条的规则文件分两处：回归规范默认值见 `.claude/rules/regression-spec.md`，
识别设计假设诊断见 `references/did-checklist.md`。默认值不等于已确认——走到这些节点
仍须停下来等研究者拍板。

第 3 条的 `CONFIRMED` 闸门是它在脚本里的落点：`05_main.R` 的参数区 `CONFIRMED`
不是 `TRUE` 就拒绝执行。`.R` 没法停下来等输入，所以**暂停在技能那侧**（`/did-estimate`
会打印规范差异表再停），**拦截在脚本这侧**——两个不同的失败模式，两道都要有。

## 九、数据阶段写法约定

数据阶段有三类错误边界模糊、出错后很难从结果里看出来。下面三条是固定的防法，
新脚本一律照做，不要逐次讨论。

### 边界一律用 `>=` 和 `<=`

年份筛写 `year >= 2010 & year <= 2019`，不写 `year > 2009 & year < 2020`。

两者在整数下等价，但变量类型从 integer 漂成 double、或年份前补过空值时结果会不同。
全项目统一一个写法，就不必每次判断「这次等不等价」。

### 样本筛选集中在 `03_clean.R`

所有筛选集中在 `code/03_clean/03_clean.R`，下游脚本（04–08）不再筛选。
下游若必须筛，把剔掉多少观测显式写进日志。

理由：描述统计的样本和主回归的样本不一致是最隐蔽的错误。两处样本数不同，
审稿人一追问就要全部重跑，而且很难定位是哪一步差的。

**唯一的例外是 `06_robust.R`**：稳健性矩阵的样本维度就是要一遍遍重切样本，
不切就做不了这个检验。例外不是豁免，附带三条约束：

1. 每一刀都必须写在 `config/robustness-matrix.R` 里，不散在代码里——
   这样「切过哪几刀」是可清点的
2. 每格都要报损，日志里逐格打印 `n0 -> n1，剔多少（百分之几）`
3. 每格的 `n_obs` 进结果文件，由 `robustness-reviewer` 核对：
   **某个「切了样本」的格子 N 和 `full` 一样，说明那一刀没切到东西**。
   这比跑失败更危险——它看上去是「做了检验」，实际上什么都没检验

### 清洗脚本末尾三条守卫，写在落盘之前

```r
stopifnot(nrow(panel) >= MIN_OBS)                          # 样本量
stopifnot(!anyNA(panel$log_emp))                           # 关键变量无缺失
stopifnot(!anyDuplicated(panel[, c("state_id", "year")]))   # 主键唯一
```

作用是拦住「AI 改代码时悄悄改变了样本规模」。只要观测数变了、关键变量有了缺失、
或主键不唯一，脚本就在写盘前中断，错误不会沉进 `data/processed/`。
比事后发现系数奇怪再回溯便宜得多。

`03_clean.R` 第 8 节把这三条写开了（各带一条能指出问题出在哪的报错），是范例。

三个坑的自动提示见 `empirical study/.claude/hooks/check_r_traps.py`。
它挂在两个事件上，行为不同：

- **PreToolUse**：只做一件事——**缺 `set.seed` 就拦住写入**（涉及随机数的
  `.R` 里找不到 `set.seed` 时 `exit 2`）
- **PostToolUse**：文件已落盘，从磁盘读成品，把四类写法提示回灌给模型
  （裸的 `year >`、非豁免文件里的 `filter()` / `subset()`、异方差稳健标准误、
  有 `feols(` 而没有 `cluster =`）

**「拦截」和「提示」的分界，判准是三条同时成立**：检查客观（有没有 `set.seed`
是事实）、没有合法例外（涉及随机数不设种子就是错的）、漏掉的后果是**静默的**
（每次跑出来的数不一样，但看上去一切正常）。三条都满足才值得拦。

其余四类只提示。它们是判断问题——`cluster` 可能确实写在别处、稳健标准误可能是
有意为之的稳健性列——拦了会误伤，而误伤几次之后人就学会忽略提示了。

**没设种子为什么值得拦，而不是提示一下就放过去。** 因为它的失败方式和
`year >` 那类不一样：边界写错，系数会明显不对；没设种子，系数**每次都在动，
而每一次看上去都很正常**。没有人会注意到。这正是「规则能表达、后果又静默」
的那一类，交给机器拦最划算。

## 十、AI 只跑代码，不读数字

**系数解读、假设判断、稳健性结论一律由研究者撰写。** Claude Code 负责把代码跑通、
把数字算出来、把运行留痕，到此为止。

理由：LLM 可能在复述它在预训练里见过的经典结果，而不是从你这份数据里估出来的
（教程点名的训练数据泄漏风险，对应 AEA 2025 披露要求）。用公开的经典数据集时
这个风险最实——模型「记得」那个系数，和它从数据里算出来那个系数，看上去一模一样。

两条可执行的机制，不是原则口号：

1. **主回归产物必须带数据指纹。** `saveRDS` + `tools::md5sum` 写进日志
   （见 `05_main.R` 第 3 节）。任何一个系数都能追到某一次运行、某一份具体的数据。
2. **脚本跑到 HITL 停止点就结束。** `05_main.R` 第 10 节打印完摘要就停，
   明写「本脚本不解读上述任何一个数字，也不写正文措辞」。

另外：**跑不出来就报「跑不出来」**，不要用近似值或记忆里的数字顶上。
这正是这条规则要防的事。

## 十一、事件研究图的 −1 期基期陷阱

若把 −1 期设为基期，该期系数被机械置零，「无预期效应（no anticipation）」这个检验
就失效了——图上看它很好地贴著 0，但那是因为它被强行设成了 0，不是估出来的。

要么把基期挪到更早（−2 期或更前），要么**不设基期、直接看全部领先项**。
`did::aggte(type = "dynamic")` 默认不设基期，所以 `05_main.R` 直接用默认值。
见 `references/did-checklist.md` 第 2 条。

## 十二、子代理的分工与边界

稳健性矩阵和表格生成走多子代理协作（教程点名的做法）。两个代理定义在仓库根
`.claude/agents/`，服务的是这条线：

| 代理 | 干什么 | 绝不干什么 |
| --- | --- | --- |
| `estimator-agent` | 按配置跑完整个矩阵，核对「配置要的格子都跑到了」，把状态和失败原文交回 | 不判系数方向，不删格不合并格，**不改配置**（尤其不改 `MATRIX_CONFIRMED`） |
| `robustness-reviewer` | 对抗式审阅：格子漏没漏、口径一不一致、**样本维度是否真的生效**、格式统不统一 | 只读不写；不判哪个格子「好」；不替研究者做取舍 |

### 代理做不了 HITL，所以闸门在配置里

代理是独立上下文，**跑完才交结果回来，没法中途暂停等人**（见
[README.md](README.md) 第六节技能与代理的分工）。所以需要人把关的环节只能在
主对话里做，代理那侧只留一道硬闸门：`config/robustness-matrix.R` 里
`MATRIX_CONFIRMED` 不是 `TRUE` 就拒绝执行。

`estimator-agent` 被明确告知不许翻这个标志位。闸门存在的意义就是拦住
「改了配置顺手一跑」——代理把它翻过来，闸门等于没有。

### 审阅必须是另一个上下文

`robustness-reviewer` 是独立上下文，**看不到写表格时的思路**。这是有意的：
如果审阅和写表在同一段上下文里，审阅会退化成复述——「我刚才是这么算的，
所以没问题」。换一个上下文，它才会去逐格对账、才会发现某个样本维度的 N
压根没变。

## 十三、稳健性矩阵的两条纪律

### 完整矩阵进附录，符号翻转的格子不许删

稳健性检验最大的诱惑是**只报告支持主结论的列**。规矩是：

- **附录放完整矩阵**，包括符号翻转的、显著性消失的、根本没跑成的
- 正文可以只展示 3-4 列，但要说明为什么这么挑
- 某格符号翻转或显著性消失，**正文里说明可能原因**，不要删
- 没跑成的格子也要在附录里有行，并写明原因

完整矩阵本身就是诚信证明。删掉一格省不了多少版面，却把「检验过」变成了
「没检验过」——而且读者看不出来。

### 「维度没生效」比「跑失败」更危险

跑失败会在结果文件里留一行 `status = "error"`，看得见。

**维度没生效是无声的**：样本规则写错了，那一格照样跑出一个漂亮的结果，
只是它的 `n_obs` 和全样本格一模一样——**那一刀根本没切到东西**。看上去
是「做了检验」，实际上什么都没检验。同类还有：结果变量换了两档而系数一位没变、
控制变量加了一列而系数纹丝不动。

所以 `robustness-reviewer` 的核查清单里，这一类是单独一节，而且要求它
**给出判断依据的原始数字**（两个格子的 `n_obs` 各是多少），不是只报一句
「疑似没生效」。
