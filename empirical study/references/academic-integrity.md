## 1. 方法选择不能自动化：APEP 的实证

HITL 节点 1（识别假设与方法选择）为什么排在第一，有一个实证案例比原则口号更有说服力。

**APEP（Autonomous Policy Evaluation Papers）**是苏黎世大学 Social Catalyst Lab
的全自动研究管线：AI 智能体从识别政策问题一路做到成稿，中途没有人类研究者介入。
据教程，截至 2026 年 3 月已产出约 592 篇论文。Paul Goldsmith-Pinkham 检视这批产物后发现，
其中 73.8% 至少三次提及 DID，**远高于 NBER 工作论文里的对应比例**——也就是说，
AI 在全自动模式下会系统性偏向 DID 这类「即插即用」的因果识别方法。

他对此的判断一句话：「很难进行因果政策评估，需要人类品味和判断。」

> **两个数字待核。** 出处是 Goldsmith-Pinkham 的博客
> [*AI one-shot papers*](http://paulgp.com/2026/03/21/ai-oneshot-papers.html)
> （2026-03-21，作者与日期已由检索结果确认）。但 **592 和 73.8% 这两个数我是从教程
> 抄来的，没能读到原文**——本环境的网页正文抓取被拦。要引用请自己开一遍原文核对。

### 这条对本仓的直接含义

本仓稳健性矩阵的估计量维度是 TWFE / CS / SA，**三档全在 DID 家族里**。
这是有意为之（它们互为负权重修正的对照），但由此有两件事要说清楚：

- **换估计量是稳健性检验，换识别策略才是换方法。** 矩阵跑得再满，也回答不了
  「这个政策问题该不该用 DID」——那是研究者的问题，矩阵在设计上就答不了
- **「跑得很顺、系数都很漂亮」不是好消息的证据。** 全自动管线正是在这种顺里出错的：
  方法适配性从来不以外报错的形式提醒你。矩阵里没有一格会告诉你「你选错了方法」

## 2. 受限原始数据不得进入会话

`CLAUDE.md` 第六节声明本项目只用公开数据（QCEW + 公开整理的最低工资史），
不涉及 WRDS / Compustat / CRSP / Wind / CSMAR。**这一节是那条声明的备用条款**：
研究方向一旦要扩到受限数据，先按第六节另建分支项目，再照这里做。

**规则：受限数据的原始文件不得以任何方式进入 Claude Code 会话。**
复制粘贴、作为附件、截图，都算违反许可协议——**即使只是让 AI 看一眼字段结构**。

**为什么连「看一眼」都不行。** 许可协议限制的是「谁能访问这份数据」，
而会话内容会离开本地机器。拖进来就构成一次未授权访问，
性质和你把文件直接发给第三方一样。

**正确做法**（本地跑，只把结构发出去）：

1. 在本地把变量清单脱敏——只留字段名、类型、取值范围，删掉任何可识别个体的值
2. 造三五行**假数据**作样例，用来看格式（日期怎么存、缺失怎么标）
3. 把「字段名 + 类型 + 假数据样例」发给 AI，让它按字段名写处理脚本
4. 脚本拿回本地跑，真数据全程不离开这台机器

**复现包里怎么处理受限数据。** 数据本身不能进包，替代物是**足够详细的重建说明**：
数据获取脚本（WRDS 的 SAS 查询语句、API 端点、申请流程）加变量构造步骤。
AEA Data Editor 接受这种处理，但**只写「数据来自 WRDS」不合格**——
第三方研究者按你的说明必须能独立重建出同一个样本。

## 4. 五个误区：本仓哪几个已经有闸门

不重复已有规则，只做对照——**哪几个坑有机器拦着，哪几个还全靠你自己**。

| 误区 | 本仓的防线 | 状态 |
| --- | --- | --- |
| 一、直接复制 AI 生成的表格 | 阶段 07 出表前强制对账：基准格必须与阶段 05 主回归同数、同指纹 | 部分——**逐列核对每张表的 N、R² 和关键系数仍是人肉一步**，闸门拦不住数字被抄错 |
| 二、用 LLM 分析经典数据集 | `CLAUDE.md` 第十节（AI 只跑代码、不读数字）+ 数据指纹 + `05_main.R` 第 10 节的 HITL 停止点 | 有——但本仓示例面板 `mpdta` **正是**经典数据集，风险实打实，见 [05_main/README.md](../code/05_main/README.md) |
| 三、把受限原始数据拖进会话 | 无 | **缺**——见本卡第 2 节 |
| 四、随机种子不固定 | `CLAUDE.md` 第二节 + PreToolUse 拦截 | 有，且是唯一会拦的一条 |
| 五、聚类层级没在披露中明示 | `.claude/rules/regression-spec.md` 规定一律显式写 `cluster = ~...` | 部分——**表脚注自动带出聚类层级还没做**，阶段 07 目前不含这一步，现在靠人记住 |

第五条的缺口值得单说：`regression-spec.md` 管的是**代码里怎么写**，
而审稿人问的「标准误是怎么聚类的」问的是**表脚注里怎么标**。两件事。
规则写对了不等于披露写全了——这是本项目自己的例子：规矩很硬，披露仍是空的。
