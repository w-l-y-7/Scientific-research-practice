# RDD 带宽与有效性清单

对应 `CLAUDE.md` 第七节第 1 条 HITL 节点。由 `method-advisor` 技能在方法选择阶段读取。

RDD 的核心优势是**断点附近近似随机**——这是它比匹配类方法强的根本原因。
但也正因为如此，**结论完全依赖带宽选择和断点的干净程度**：带宽一改结论就变，
或者有人能精确操纵自己在断点的哪一侧，整个设计就失效。

每一条都要在 `code/01_identify/` 的决策记录里留下检验结果。**没有检验结论的假设，
不能当作成立**——写「未检验」比默认它满足要安全。

## 1. 带宽选择

- 条款：只有在断点邻域内，断点两侧的个体才近似可比。带宽越宽样本越多，但可比性越差
- 检验：**必须报多个带宽下的结果**，不能只报一个
- 命令：`rdrobust::rdrobust(y, x, c = cutoff)` 用 MSE 最优带宽；
  再用 `h = ...` 手动指定若干带宽对照
- 陷阱：数据驱动的最优带宽（IK / CCT 方法）**会掩盖敏感性**。
  正文里要同时给最优带宽和 ±50% 的对照，系数符号变了就得解释

## 2. 操纵检验（Manipulation / Density Test）

- 条款：个体不能精确控制自己落在断点的哪一侧
- 检验：断点附近驱动变量的密度是否连续；协变量在断点两侧是否平衡
- 命令：`rddensity::rddensity(x, c = cutoff)` 做密度检验；
  `rdplot::rdplot(y, x, c = cutoff)` 看驱动变量分布
- 陷阱：**密度连续不等于没操纵**。如果个体操纵的是协变量而不是驱动变量本身，
  密度检验照样通过。要同时看协变量平衡

## 3. 协变量平衡

- 条款：断点两侧的**前定**协变量应当连续（不因处理而跳变）
- 检验：把每个前定协变量当结果变量跑一遍 RDD，系数应不显著
- 命令：`rdrobust::rdrobust(covariate, x, c = cutoff)` 逐个跑
- 陷阱：这里只能放**前定**变量。放处理后变量会把处理效应本身当成"不平衡"，
  是常见的错误操作

## 4. 带宽内样本量与子群

- 条款：断点邻域内的有效样本要够，否则估计量方差极大
- 检验：报出各带宽下的有效观测数（`rdrobust` 的 `N_h` 字段会给出断点两侧各自的有效 N）
- 陷阱：断点一侧样本极少时（比如只有几十个），有效 N 由**较小的一侧**决定，
  不是总样本量。总样本十万但断点右侧只有 20 个，这个 RDD 跑不动

## 5. 模糊断点（Fuzzy RDD）

- 条款：断点不是强制性的——越过断点只是提高接受处理的概率，不是必然接受
- 检验：`rdrobust::rdrobust(y, x, c = cutoff, fuzzy = d)`；此时估的是 LATE 不是 ATE
- 陷阱：模糊 RDD 里第一阶段也要检验（同 [iv-validity.md](iv-validity.md) 第 1 条），
  断点处处理概率的跳跃若不显著，等于一个弱工具

## 6. 甜甜圈洞与稳健性

- 条款：紧贴断点的观测可能被操纵，或测量误差在断点附近最严重
- 检验：剔除断点附近 ±δ 的观测重跑（donut hole），看结论是否稳定
- 陷阱：donut 半径要靠制度背景定，不能试到"结果好看"为止——
  那就是在挑设定，不是在做稳健性

## 7. 报告要求

- 必须报：最优带宽 + 至少两个对照带宽、有效 N（分断点两侧）、`rdplot` 图、
  密度检验、协变量平衡表
- 结论措辞按 [README.md](../README.md) 第六节红线：写「在断点附近近似随机的假设下，
  估计结果支持……」，**不写成「已证明」**；且效应只对断点邻域内的个体成立，
  外推到全体是常见误读
