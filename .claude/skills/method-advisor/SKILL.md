# method-advisor：方法选择的辅助，不是方法选择

**这个技能的天花板很低，而且是有意的。** 它把研究问题映射到假设检查单、
把候选方法摆全、标出每个选项依赖什么，然后**停下来把决定权交回去**。

不替研究者选，是因为识别策略错了，后面所有估计的可信度归零，
而这个错误无法通过更仔细的代码或更多的稳健性检验补回来。

## 适用范围

本技能服务 `empirical study/` 那条线（实证研究）。根目录的文献综述流水线不用它。

## 第 0 步：确认输入够不够

动手前需要三样东西。缺任何一样就**停下来问用户**，不要替他假设：

1. **研究问题**：处理是什么、结果是什么、机制是什么
2. **数据结构**：截面 / 面板 / 时间序列；有没有个体维度和时间维度；跨度多长
3. **处理是怎么发生的**：有没有外生冲击、有没有阈值或断点、处理时点是统一还是渐进

第 3 条最常缺，而它恰恰是分叉的关键。如果用户没说处理时点是否渐进，
**问一句**「各州/各单位是在同一年接受处理，还是不同年份陆续接受？」——
这一句决定了是 TWFE 还是 Callaway-Sant'Anna。

## 第 1 步：读方法卡

读 `empirical study/references/` 下相关的卡。**不要凭记忆复述假设清单**——
卡里写的是本项目的口径，记忆里的可能对不上：

| 卡 | 什么时候读 |
| --- | --- |
| `did-checklist.md` | 候选里有 DID / TWFE / Callaway-Sant'Anna |
| `iv-validity.md` | 候选里有 IV / 2SLS |
| `rdd-bandwidth.md` | 候选里有 RDD |

这些卡也可能被研究者改过，所以每次都重新读，不缓存。

## 第 2 步：走决策树

```
研究问题确立
├── 有明确的外生冲击变量？
│   └── 是 → 工具变量 IV（ivreg::ivreg / fixest::feols 的 IV 语法）
└── 否
    ├── 有阈值或断点规则？
    │   └── 是 → 断点回归 RDD（rdrobust::rdrobust）
    └── 否
        ├── 有处理时点变化的面板？
        │   └── 否 → 横截面或匹配方法
        └── 是
            ├── 处理时点统一（单时点）？
            │   └── 是 → 传统 DID / TWFE（fixest::feols）
            └── 否（渐进采纳）
                ├── 控制组充足？ → Callaway-Sant'Anna（did::att_gt）
                └── 控制组少于 5 个？ → 合成控制 / SDID
```

树只给粗线条。每个节点还要追加细节——IV 的相关性和排他性站不站得住、
RDD 的带宽怎么选、DID 的平行趋势能不能用事件研究可视化。
**这些不写在树里，写在方法卡里。**

## 第 3 步：输出（固定三段，不要多写）

```markdown
推荐方法：<方法名>

三个支持理由：
1. <来自数据的结构特征>
2. <来自方法学文献的问题，比如渐进采纳下 TWFE 的负权重>
3. <来自数据结构的具体条件，比如控制组是否充足>

需要你亲自确认的假设：
A. <假设名>：<这个假设在本设计里意味着什么><怎么诊断>
B. <假设名>：<...>

我不做最终决定。这两项请你判断后再进入主回归。
```

**必须有最后那句。** 不是客套——它是这个技能的定位声明。

## 红线

- **不说「应该用 X」，只说「推荐 X，理由是……，但 A 和 B 要你确认」。**
  措辞差别在责任归属：前者是替决策，后者是辅助决策。
- **不编造文献。** 理由要引用真实存在的方法学结论（如 Goodman-Bacon 2021
  关于 TWFE 负权重）。拿不准就不引，写「这一点我没把握，请核」。
- **不替研究者判断假设成立与否。** 平行趋势、排他性这些假设**本身不可直接检验**，
  只能间接诊断。技能的角色是告诉他「你要承担这个假设」，而不是「这个假设通过了」。
- **不给数据怎么收集的建议。** 那是阶段 2 的事，本技能只服务方法选择。
- 建议的方法若要落到代码，**不要在本技能里写 R 代码**。
  执行是 `did-estimate` 技能和 `empirical study/code/05_main/05_main.R` 的事。

## 下一步

方法定了之后：去 `empirical study/code/01_identify/` 把决策记录写下来
（假设、依据、待检验项），然后进阶段 3 清洗；到主回归时用 `/did-estimate`。

**这一步的产物要留痕。** `did-checklist.md` 开头写着「没有检验结论的假设，
不能当作成立」——决策记录就是这句话的落点。
