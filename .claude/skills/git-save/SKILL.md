# git-save：先拦垃圾，再一键提交推送

把「扫垃圾 → 写 .gitignore → 暂存 → 提交 → 推送」串成一条龙。合并了原来的 git-ignore：**每次保存前都会先过一遍不该入库的文件**，避免密钥、缓存、脚本产物混进仓库。

分工原则：**明确的垃圾自动拦，需要判断的问一次，其余全自动。**

## 触发条件

用户表达想保存 / 提交 / 推送当前 git 改动，就用本技能，哪怕只说「存一下」。不必等用户说全「git add commit push」。

---

## 执行步骤

### 第 0 步：先扫垃圾文件（提交前必做）

#### 0.1 收集情报（只跑命令，不翻文件内容）

两条命令把全场扫出来，路径统一加 `-c core.quotepath=false`，中文文件名才不乱码：

```powershell
# 1) 没被跟踪、现在也没被忽略的文件（= 下次提交会带上的）
git -c core.quotepath=false ls-files --others --exclude-standard

# 2) 已被跟踪的文件全名单（= 已提交进仓库的，拿来认漏网的垃圾）
git -c core.quotepath=false ls-files
```

再用 Read 工具读现有 `.gitignore`（UTF-8），记住已有哪些规则，别重复加。

> 第 1) 条会自动尊重各级 `.gitignore`，所以没出现在结果里的，就是已经被规则挡住的，不用管。

#### 0.2 归类

拿上面的名单，对照「垃圾特征表」认人。看到什么归什么，别硬凑。

| 类别 | 特征 | 例子 |
| --- | --- | --- |
| **B 依赖/缓存目录** | 目录名叫 `node_modules`、`.venv`、`venv`、`__pycache__`、`.pytest_cache`、`.mypy_cache`、`dist`、`build`、`.next`；或文件是 `*.pyc` | 删了能重装 |
| **C IDE/系统文件** | `.vscode`、`.idea`、`.DS_Store`、`Thumbs.db`、`desktop.ini`、`*.swp` | 每台电脑都不一样 |
| **D 隐私/密钥** | `.env*`、`*.pem`、`*.key`、`*.p12`、`*.db`、`*.sqlite*` | 里面是密码/密钥，提交等于泄露 |
| **A 脚本跑出来的产物** | `*.csv`、`*.png`、`*.jpg`、`*.log`、`*.aux`、`*_report.csv` 这类，且名字像「跑一次脚本生成的」 | 有代码在的话重跑就能再生成 |

**三条铁律：**

- **源代码、脚本本身（`*.py`、`*.js`、`.ps1`、`.sh` 等）、文档、项目配置文件，一律不归为垃圾**，这些是要提交的成果。
- **一条规则只写具体路径**，别图省事写一刀切的 `*.csv`、`*.png`（下次真想提交一张图就误伤了）。
- **拿不准就放进待问清单**，绝不擅自归类。

#### 0.3 直接拦下不问的（B / C / D）

这三类特征明确，写进 `.gitignore`，不用问用户：

- **B、C**：明摆着的编译/缓存/系统文件，拦了不影响任何东西
- **D**：密钥类文件，拦下来是安全收益，拦完要在汇报里**点名提醒用户**（「发现 X 个疑似密钥文件已拦下」）

#### 0.4 需要问一次的（A 类 + 拿不准的）

A 类产物和判断不了的文件，整理成清单**问一次**（AskUserQuestion 或直接对话），三类选项供选：

```
[A 脚本产物]   backtest_report.csv / equity_curve.png
[拿不准]       data/raw_prices.csv —— 是原始数据还是要丢掉？
[建议提交-别忽略] run_backtest.py / config.yaml
```

顺手明确告诉用户哪些是**建议提交的代码**，别当成垃圾忽略了。

用户说「都不要」或啥都不剩 → 跳过写 `.gitignore`，直接进第 1 步。

#### 0.5 写进 .gitignore（只写确认过的）

新增规则放一个带标记的分区，方便以后认出来、也好删：

```
# ===== git-ignore 自动整理 <今天的日期> =====
## B 依赖/缓存目录
...
## A 脚本跑出来的产物
...
```

- 文件**已存在**：只**追加**，绝不整体重写（旧文件里可能有被 GBK 写坏的乱码注释，一重写就真坏了）：
  ```powershell
  $block = @'
  规则1
  规则2
  '@
  Add-Content -Path .gitignore -Encoding utf8 -Value $block
  ```
- 文件**不存在**：用 Write 工具新建 UTF-8（无 BOM）。
- 加之前跟现有规则**去重**；子目录已有 `.gitignore` 且覆盖了，就别在根目录重复加。

#### 0.6 已跟踪的垃圾：取消跟踪（必须问）

若第 2) 条名单里发现早就提交进去的垃圾，只能靠取消跟踪清掉——**这一步必须问过用户再动**：

```powershell
git rm --cached "相对路径/文件名"
```

`--cached` 的意思是只从 git 账本里划掉，**硬盘上的文件原样保留**。绝不能漏掉 `--cached`，漏了就是真删用户文件。

---

### 第 1 步：看清有什么改动

- `git status`：区分已跟踪改动（modified / deleted）与未跟踪新文件。
- `git diff` + `git diff --cached`：读改动内容。改动多时先 `git diff --stat` 看概览，再抽样读几处正文。
- 工作区干净（nothing to commit）→ 告诉用户「没有需要提交的改动」，到此为止。

### 第 2 步：全量暂存

- 执行 `git add -A`。第 0 步刚写好的 `.gitignore` 已负责排除垃圾，不用手动挑文件。
- 暂存后跑 `git status` 复核将要提交的文件清单。

### 第 3 步：异常文件守卫（唯一的例外，遇到才停下）

要提交的文件里混入明显不该入库的东西时，停下来问用户，不静默提交：

- 密钥/凭据：`.env*`、`*id_rsa*`、`*.pem`、含 `credential` 的文件
- 体积异常大的文件

### 第 4 步：生成提交信息并提交

- 用中文概括（保持仓库历史风格一致），一句主题行说清做了什么，必要时加简短正文。
- 点出涉及的主要文件或改动性质，便于日后回退辨认。别写「update」「保存一下」这种没信息量的。
- 格式 `<type>: <description>`，类型用 feat / fix / refactor / docs / test / chore。示例：`docs: 补充周报模板的数据一览`。
- **不添加 Co-Authored-By。**
- 执行 `git commit -m "..."`；需要多行时用多个 `-m` 拼主题行 + 正文。

### 第 5 步：推送到远程

- 先 `git remote -v` 确认远程存在。**若为空，不擅自添加远程**，停下来告诉用户需要提供远程地址。
- 执行 `git push`。
- 若报「当前分支没有上游」：用 `git branch --show-current` 取分支名，改跑 `git push -u origin <分支名>`。
- **禁止 `git push --force`。**

### 第 6 步：汇报结果

一两句话说明：提交了哪些内容、commit 短 hash、是否已推送。若第 0 步动过 `.gitignore`，一并说清加了哪几条规则、拦下了什么。**任何一步出错，如实报告失败原因和补救办法，不假装成功。**

---

## 红线

- **永远不 `git rm`（不带 `--cached`）真删文件**；最多 `git rm --cached`。
- **绝不忽略源代码、脚本、文档、配置文件**——那是用户的成果。
- **不擅自加远程、不 force push、不 `--no-verify` 绕过 hook。**
- `.gitignore` 里有乱码注释（中文变「锟斤拷」那种）**别去重写修复**，编码已坏、重写更糟，只追加新分区。
- 拿不准就停下来问，别猜。
