# did-estimate：跑主回归，但不解读它

这个技能把「执行」和「解读」切开。执行这一段它做得又快又全，解读那一整段它不碰。

那条线不是客套，是教程点名的训练数据泄漏防线：LLM 可能在复述它在预训练里见过的
经典结果，而不是从你这份数据里估出来的。用公开的经典数据集（比如 `did` 包自带的
`mpdta`）时最危险——模型「记得」的系数和它从数据里算出来那个，看上去一模一样。
界画在「**AI 跑代码、人读数字**」，见 `empirical study/CLAUDE.md` 第十节。

## 适用范围

服务 `empirical study/` 那条线（实证研究）。根目录的文献综述流水线不用它。

## 第 0 步：确认前提

- 识别策略定了吗？没定先去 `/method-advisor`。**策略没定就跑主回归是白跑。**
- `empirical study/data/processed/panel.rds` 在吗？
  - **不在也不一定要停**——`05_main.R` 的 `PANEL_SOURCE = "mpdta"` 这条路线
    用 `did` 包自带的示例面板，跳过数据拉取和清洗，专门用来把方法跑通。
    先问清楚这次跑的是哪条路线。
- R 装了吗？没装就说明要装什么（`empirical study/README.md` 第五节），然后停。

## 第 1 步：前置检查，然后**停下**

**读 `empirical study/code/05_main/05_main.R` 的参数区，原样打印。**
不要复述、不要转述、不要从记忆里写——参数区是唯一真源，转述一遍就会漂。

然后做两件事：

### 1a. 和项目默认值并排比

读 `empirical study/.claude/rules/regression-spec.md`，把**本研究取值**和
**项目默认值**并排列出来，逐项标「一致 / 不一致 / 规范里没写」：

| 参数 | 本研究取值 | regression-spec.md 默认 | 差异 |
| --- | --- | --- | --- |
| （从脚本参数区逐项填） | | | |

**不一致的项要显式点出来**，不要因为「看着差不多」就跳过。不一致本身不是错——
研究设计可以偏离默认值，但必须是有意的，而且要在正文里说明。

### 1b. 按 did-checklist 列出待检验的假设

读 `empirical study/references/did-checklist.md`，挑出这次设计真正涉及的条目
（平行趋势、无预期效应、SUTVA、负权重、聚类层级），每条写：
**假设是什么 / 怎么诊断 / 诊断结果在哪看**。

**不要替研究者判断假设成不成立。** 平行趋势这类假设本身不可直接检验，只能间接诊断。
技能的角色是告诉他「你要承担这个假设」，而不是「这个假设通过了」。

### 1c. 停下

打印完 1a 和 1b 就**停下来等确认**。不要顺手往下跑。

脚本那侧还有一道 `CONFIRMED` 闸门：参数区 `CONFIRMED` 不是 `TRUE` 就拒绝执行。
两道闸门防的是两个不同的失败模式——技能这侧防「没想清楚就确认」，
脚本那侧防「未确认的裸跑」（改了参数顺手一跑、系数变了而没人察觉）。
**两道都要有，不要绕过其中任何一道。**

## 第 2 步：执行

```powershell
cd "empirical study"
Rscript code/05_main/05_main.R
```

或者在 RStudio 里 `source("code/05_main/05_main.R")`。

**不要在这里重述步骤清单。** `05_main.R` 的分节就是清单，它是唯一的执行真源；
抄一遍就会漂，然后代码改了技能没改，两边对不上。

脚本报错时按其打印的指引回退，**不绕过**：

| 报错 | 含义 | 怎么办 |
| --- | --- | --- |
| `未确认，已中止` | `CONFIRMED` 不是 `TRUE` | 回第 1 步，确认后由**研究者**改 |
| `面板里没有这些变量` | 参数区和数据的列名对不上 | 照报错里打印的实际列名核对参数区 |
| `gvar 缺失` / 指向 `03_clean.R` 第 7b 节 | 真面板那条线没有 `gvar` | 补外部政策文件后重跑 `03_clean.R`，或改走 `mpdta` 路线 |
| 观测数低于守卫下界 | `MIN_OBS` 和样本对不上 | 查样本是不是被改动了 |
| `缺少这些 R 包` | 依赖没装 | 把脚本打出来的 `install.packages(...)` 转给研究者，**不要自己装** |

## 第 3 步：HITL 输出

跑完**把产物交出去，然后停**。呈现这几项，不加工：

- 样本量、单位数（县/州数）
- `aggte(type = "simple")` 的汇总 ATT 与标准误
- CS-DID 与 TWFE 的系数差（脚本第 8 节会算）
- 事件研究图路径、系数表路径、日志路径（含数据指纹）

然后明确要求研究者核对：

1. **事件研究图的处理前各期系数**是否接近 0（平行趋势的间接诊断）
2. **−1 期有没有被当基期置零**——若设了基期，该期系数被机械置零，
   「无预期效应」这个检验就失效了。`aggte(type = "dynamic")` 默认不设基期，
   确认脚本用的是默认值（见 `did-checklist.md` 第 2 条）
3. CS-DID 与 TWFE 的差异怎么在正文里解释
4. 这个 ATT 在经济上意味着什么

**不解释、不总结、不写正文措辞。** 也不要说「结果显著，说明政策有效」这类话——
那正是本技能要防的事。

## 红线

- **不解读系数。** 不说方向、不说大小、不说显著性意味着什么。
- **不判断假设成立与否。** 只指出「这一条要你判断」，不替他判。
- **不写正文措辞。** 那是阶段 8 的事，且必须研究者定稿。
- **不编造数字。** 脚本跑不出来就报「跑不出来」，让它缺着，
  不用近似值或记忆里的数字顶上。
- **不在本技能里写 R 代码。** 执行真源是 `05_main.R`；需要改就改那个文件，
  不要在这里另起一份。
- **不绕过 `CONFIRMED` 闸门。** 不替研究者改 `TRUE`。

这是最贵的返工点，所以第 3 步的「停下来」不能省。
